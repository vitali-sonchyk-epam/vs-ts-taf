## Findings

### Blocking

- **src/ui/components/EstimationModal.ts:24** — XPath scoping regression. The original WebdriverIO locator used `.//div[@role="button"][...]` (leading dot), scoping the search to descendants of the modal root. The Playwright version drops the leading dot: `this.rootElement.locator('//div[@role="button"]')`. A chained Playwright locator whose XPath starts with `//` (no leading `.`) is evaluated against the *whole document*, not relative to `rootElement`. It currently only "works" because `.filter({ hasText: label })` narrows to a specific text, but the scoping guarantee is lost — it can pick up an unrelated `div[role="button"]` elsewhere in the DOM with matching text, and no existing test would catch that false positive. Fix: restore the leading dot — `.//div[@role="button"]`.

### Suggestions

- **src/ui/pages/CloudSQL.page.ts:8-10** — Leftover stub `protected get title(): string { throw new Error('Method not implemented.'); }`. Nothing references `.title` (the code uses `getTitle()` instead); this looks like debris from an earlier refactor and should be removed since invoking it would throw.
- **src/ui/pages/Welcome.page.ts** — `WelcomePage` now extends `BaseCalculatorPage`, inheriting a `getTitle()` scoped for calculator sub-pages even though the welcome/landing page isn't itself a calculator page. Nothing currently calls `welcomePage.getTitle()`, but the inheritance is semantically questionable; consider a lighter shared base (plain `BasePage`) instead.
- **src/ui/pages/CloudSQL.page.ts / src/ui/pages/ComputeEngine.page.ts** — Duplicated `numberOfInstancesInput`/`totalUsageLimitInput` getters and near-identical `setNumberOfInstances`/`getTotalUsageLimit` methods (same selectors `div.QiFlid`/`div.KDALvb`). Worth hoisting into `BaseCalculatorPage` — the duplication already caused drift: `ComputeEnginePage.getTotalUsageLimit` logs the read value via `Logger.info`, while `CloudSQLPage.getTotalUsageLimit` does not.
- **playwright.config.ts:14** — `workers: 16` is hardcoded, which may be too aggressive for smaller CI runners and doesn't scale with available cores the way Playwright's default (auto-detected) does. Consider `process.env.CI ? <n> : undefined`.
- **src/utils/Logger.ts:9-19** — `void Promise.resolve(logStep(...)).catch(() => undefined)` silently swallows *all* errors from `logStep`, not just expected "no active Allure test" errors. This could hide real integration bugs during development; consider logging the swallowed error for visibility.
- **README.md** — the "Project structure" tree still reflects the old layout (`Calculator.page.ts`, no mention of `CloudSQL.page.ts`, `ComputeEngine.page.ts`, the new `base/` directory, `constants/tags.ts`, or the new test files), even though prose elsewhere was updated to Playwright terminology.
- **package.json** — all dependencies moved under `devDependencies` with no `dependencies` block. Reasonable for a test-only project, but worth a deliberate confirmation since the previous file had a `dependencies` section.
